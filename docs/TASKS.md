# TASKS.md

港交寶是一套 AI agent skill。它向代理提供一套技能，代理用技能裡的指令回答市民的交通問題。技能本身不跟市民對話，也不替市民選定行程。

每個指令是一段可重用程式，回答一整類問題，回傳可序列化的 JSON。每次結果都要帶三樣東西：資料集編號、實際查過的端點，以及數據本身的時間（香港時間）。檔案沒有時間欄時，標明檔案的更新頻率，並把「擷取時間」同「數據時間」分開寫。一個答案讀幾份來源時，這三樣都可以是清單，逐個來源的資料另放 `sources`。資料沒有的欄位留空並說明，不編造。

後面的階段尚未決定。路線圖同每個階段要交的五樣東西寫在 [README](../README.md)。任何階段開工前，先在這裡寫明該階段的範圍。

## 第一階段 — 港鐵（完成）

涵蓋港鐵本地重鐵、機場快線、迪士尼線、輕鐵，以及輕鐵接駁的港鐵巴士。資料來自 data.gov.hk 上港鐵的 4 個數據集。2026-10-29 核對過下列端點可以取到資料。

| 資料 | 資料集編號 | 端點 |
|---|---|---|
| 路線、車站、車費、無障礙設施 | `mtr-data-routes-fares-barrier-free-facilities` | 見各任務的 CSV |
| 重鐵下一班（含機場快線、迪士尼線） | `mtr-data2-nexttrain-data` | `https://rt.data.gov.hk/v1/transport/mtr/getSchedule.php` |
| 輕鐵下一班 | `mtr-lrnt_data-light-rail-nexttrain-data` | `https://rt.data.gov.hk/v1/transport/mtr/lrt/getSchedule` |
| 港鐵巴士到站時間 | `mtr-mtr_bus-mtr-bus-eta-data` | `POST https://rt.data.gov.hk/v1/transport/mtr/bus/getSchedule` |

重鐵下一班涵蓋機場快線、東涌線、屯馬線、將軍澳線、東鐵線、南港島線、荃灣線、港島線、觀塘線、迪士尼線，每個方向最多 4 班，約每 10 秒更新。

這一階段刻意不做：頭班車與尾班車、去某座大廈該行哪個出口、車廂或月台擠迫程度、高速鐵路、城際客運。重鐵站出入口座標見下面的 `mtr_exits`。公開數據沒有公布的行車分鐘，也沒有轉車步行時間。`mtr_ride_estimate` 只在相鄰站的實時班次對得齊時估算車上分鐘；對不齊就留空全程。城際客運 CSV 在同一路線數據集裡，不讀。

### 1.1 路線與車站（完成）

對應問題：觀塘線有哪些站？金鐘是哪幾條線的轉車站？

做一個路線與車站查詢。讀 `https://opendata.mtr.com.hk/data/mtr_lines_and_stations.csv`。欄位是路線代碼、方向、車站代碼、車站編號、中文名、英文名、站序。

東鐵線有羅湖和落馬洲兩條分支（方向 `DT`／`UT` 與 `LMC-DT`／`LMC-UT`）。將軍澳線有康城分支（`TKS-DT`／`TKS-UT`）。查「一條線的車站」時要按方向交還，不能把分支壓成一條順序。

完成時能回答：

- 一條線、一個方向上的車站順序。
- 一個車站代碼或中文名屬於哪些線。

### 1.2 兩站之間的轉乘路徑（完成）

對應問題：由柴灣去荃灣，乘哪條線，在哪一站轉車，中間停哪些站？

用 1.1 的站序組出一條路徑：沿哪些線、在哪個共用車站編號轉車、中間停哪些站。轉車站以共用的車站編號辨認，例如金鐘、旺角、太子。

機場快線的香港站（編號 44）、東涌線的香港站（編號 39）、荃灣線和港島線的中環站（編號 1）是不同編號。指令要把這三個站當成同一個轉乘點，不能當成三個不相通的站。東鐵線和將軍澳線的分支要沿正確方向走。

這份資料沒有行車時間。路徑結果不填分鐘。車上分鐘的估算見 1.10。

完成時能回答：柴灣到荃灣的轉線車站與沿途車站。兩站在同一條線上時，結果沒有轉車。

### 1.3 重鐵車費（完成）

對應問題：由中環去紅磡，八達通同單程票幾多錢？成人、小童、長者、學生、樂悠咭、殘疾人士各幾多？

讀 `https://opendata.mtr.com.hk/data/mtr_lines_fares.csv`。車費是站對站，跟 1.2 的路徑無關。交還檔案裡實際有的欄：八達通成人、學生、樂悠咭（60 歲）、小童、長者、殘疾人士，以及單程票成人、小童、長者。

完成時能回答：任意兩個重鐵站、上述每一種票的車費。某一種票在檔案裡不存在時，該欄留空並說明，不拿另一種票頂替。

### 1.4 重鐵下一班與車務狀態（完成）

對應問題：我在金鐘、港島線往柴灣，下一班幾時到？哪個月台？終點站是哪？而家這條線有沒有特別車務安排？

讀 `https://rt.data.gov.hk/v1/transport/mtr/getSchedule.php`，參數是路線代碼同車站代碼。交還每個方向最多 4 班：到站或開出時間、終點站、月台，以及 API 的狀態碼、警報文字、特別安排連結。時間用 API 回傳的 `curr_time`，標明香港時間。

機場快線和迪士尼線走同一個 API，不另做一個下一班指令。

完成時能回答：金鐘、港島線往柴灣的下一班。API 有警報時，答案帶出警報文字和連結，note 是「這一站這一線的回應有特別安排。全港特別交通消息要再查 special_traffic_news。」這個函式不代為下載那份全港消息。API 沒有警報時，明白寫「這次回應沒有特別安排」，不寫成「全線正常」。API 沒有交 `status` 時，寫「這次回應沒有車務狀態，不能說有沒有特別安排」，不當成正常。

### 1.5 機場快線車費（完成）

對應問題：機場快線由香港站或九龍站去機場、博覽館，成人同小童幾多錢？

讀 `https://opendata.mtr.com.hk/data/airport_express_fares.csv`。這份檔同 1.3 分開，欄位只有八達通成人、八達通小童、單程票成人、單程票小童。下一班用 1.4。

完成時能回答：香港、九龍、青衣往機場或博覽館的成人同小童車費。不把重鐵的長者、學生或樂悠咭車費套到機場快線。

### 1.6 車站無障礙設施（完成）

對應問題：這個站有沒有升降機、寬閘、無障礙洗手間？在哪個出口？

讀兩份 CSV：

- 設施種類：`https://opendata.mtr.com.hk/data/barrier_free_facility_category.csv`
- 各站設施：`https://opendata.mtr.com.hk/data/barrier_free_facilities.csv`

各站檔以車站編號、設施鍵、有或沒有、出口文字（中英）記錄。用種類檔把設施鍵譯成可讀名稱。只交還標成有的設施。出口座標欄多數是空的；空就留空。

完成時能回答：一個車站有哪些無障礙設施、在哪個出口。這不是「去某座大廈行哪個出口」。升降機只分「閘外區域」同「已付車費區域」，資料沒有樓層，所以不可以答成「直達地面」。

### 1.7 輕鐵下一班（完成）

對應問題：輕鐵元朗站下一班是幾號、去哪、還有幾多分鐘？是不是特別班？

讀 `https://rt.data.gov.hk/v1/transport/mtr/lrt/getSchedule`，參數是 `station_id`。交還月台、路線號、目的地中英文、剩餘時間、到站或開出、車卡數目、是否特別班。`with_special=1` 時包含特別班。時間用 API 的 `system_time`，標明香港時間。

完成時能回答：元朗站（或其他一個輕鐵站）即將開出的班次，並標出哪些是特別班。

### 1.8 輕鐵路線與車費（完成）

對應問題：輕鐵由屯門去元朗幾多錢？610 線停哪些站？

讀：

- `https://opendata.mtr.com.hk/data/light_rail_routes_and_stops.csv`（路線、方向、站序、中英文站名）
- `https://opendata.mtr.com.hk/data/light_rail_fares.csv`（站對站：八達通成人、小童、長者、殘疾人士、學生、樂悠咭；單程票成人、小童、長者）

完成時能回答：一條輕鐵線一個方向的車站順序，以及兩個輕鐵站之間檔案裡有的各種車費。

### 1.9 港鐵巴士（完成）

對應問題：港鐵接駁巴士 K52 停哪、車費幾多？這一站下一班幾時到？

讀三份每月 CSV，加一個實時 API：

- 路線：`https://opendata.mtr.com.hk/data/mtr_bus_routes.csv`
- 車站：`https://opendata.mtr.com.hk/data/mtr_bus_stops.csv`（含緯度、經度）
- 車費：`https://opendata.mtr.com.hk/data/mtr_bus_fares.csv`（以路線為單位，不是分段車費）
- 到站：`POST https://rt.data.gov.hk/v1/transport/mtr/bus/getSchedule`，JSON 主體是 `language` 同 `routeName`

車費欄包括八達通同單程票的成人、小童、長者、樂悠咭、殘疾人士、學生。到站結果交還 API 回傳的各站下一班，並保留「預定班次」與「實時位置」的分別。規格以港鐵現行數據字典為準（2026-09-28 有修訂）。

完成時能回答：K52 的停站順序、該路線的車費，以及沿線各站的下一班。

### 1.10 車上時間估算（完成）

對應問題：由長沙灣去海洋公園，車上大約幾耐？

指令是 `mtr_ride_estimate`。路徑用 1.2，不另寫一套尋路。沿途每個站用 1.4 的 `next_train`，只保留開往該方向終點站的班次。兩個方向分開計：同一方向的到站時間互相對，找出最受支持的分鐘差。至少兩班車同意同一個分鐘，而且沒有另一個分鐘有同樣多班車同意，才採用。這個 API 不以車次編號跨站配對，所以指令不聲稱已確認是同一班車；兩班不同車同意同一個分鐘，就是這個方法的上限，寧願留空。不設固定的分鐘上限。兩站時鐘相差幾秒時會出現 0 分鐘的配對；0 分鐘只用來否決其他配對，不會當成車程。

結果交還每一段的 `minutes`。全部段都對得齊時，全程 `minutes` 是各段之和。任何一段對不齊，全程 `minutes` 留空，其餘段仍逐段交還，並在 note 寫明哪一段對不齊。

這不是港鐵公布的行車時間。同一站連續兩班相減是班距，不用。停站時間已經在兩站的差距裡，不每站再加 30 秒。轉車步行和月台等車不在這個估算裡。

完成時能回答：對得齊的路段各要幾分鐘；對不齊時說明沒有全程總數。

### 地址查詢（完成）

對應問題：元州商場在哪？這個地址的座標是多少？

這不是港鐵數據集。核心函式 `address_lookup` 讀地政總署地址查詢服務，資料集 `hk-dpo-als_01-als`，端點 `https://www.als.gov.hk/lookup?q=`，請求要帶 `Accept: application/json`。舊網址 `als.ogcio.gov.hk` 不使用。

交還每個匹配的中英文大廈、屋苑、街道、門牌、地區、緯度、經度、北距、東距，以及匹配分 `score`。查詢沒有數據時間。不快取。`score` 不是距離。服務會為對不上的字串仍交還建議，呼叫的人要看分數。

這個函式不挑選最近的車站，也不把結果接上路線表。重鐵站出入口座標在 `mtr_exits`。最近車站要另組合這兩個結果，不在這裡另寫一套地址搜尋。

完成時能回答：一個地名或地址的匹配結果同座標。

### 重鐵出入口座標（完成）

對應問題：這個站有哪些出口？出口的座標是多少？

核心函式 `mtr_exits` 讀一份已存好的重鐵出入口快照，不在查詢時上網。來源是地政總署地理位置搜尋 `hk-landsd-openmap-development-location-search-api`，端點 `https://www.map.gov.hk/gs/api/v1.0.0/locationSearch`。每個站以官方中文站名搜尋 `港鐵{站名}站 出口` 一次。只保留站名對得上、名稱以「出口」結尾的結果，包括「進出口」和「出口」。舊網址 `geodata.gov.hk` 不使用。

搜尋回應的 x、y 是香港1980方格網的東距、北距，不是經緯度。緯度、經度另由 `hk-landsd-openmap-coordinates-transformation-api` 轉一次後寫進同一份快照。

出入口幾乎不變，這份快照約一年內重用，不放進 30 日的 `.cache/`。檔案是 `src/hk_transport/data/mtr_exits.json`。2026-10-29 的快照有 97 個重鐵站、608 個出入口。超過一年仍交還同一份，並在 note 說明。這不是港鐵公布的出口名冊。輕鐵站不在這份表。羅湖和落馬洲的名稱用「出口」，其餘多是「進出口」。青衣、九龍、香港在機場快線和東涌線各有一個車站編號，同一組出入口的 `station_ids` 兩個都列。這個函式不計算最近的車站。

完成時能回答：一個重鐵站各出口的東距、北距、緯度、經度。`mtr.sh` 一定要給一個站名；沒有這個站時 `data` 留空並在 note 說明。核心函式不給站名時交還整份快照，留給要跨站比較的程式用。

### 特別交通消息（完成）

對應問題：而家有什麼特別交通消息？有沒有封路或改道？

這不是港鐵數據集，後面的交通系統也用同一份。核心函式 `special_traffic_news` 讀運輸署特別交通消息第二代，資料集 `hk-td-tis_19-special-traffic-news-v2`，端點 `https://www.td.gov.hk/tc/special_news/trafficnews.xml`。英文網址目前交還同一份檔，繁體中文在 `CONTENT_CN`。第一代網址不使用。

每則消息交還事故編號、標題、詳情、地點、方向、宣布時間、狀態、附近地標、中英文內文。沒有座標就留空。宣布時間標成香港時間。整份清單都交還，不按「港鐵」或其他關鍵字篩選。不快取。現時沒有消息時，note 寫「現時沒有特別交通消息」。

港鐵某一線、某一站的延誤或暫停仍看 1.4 的 `mtr_next_train`。`status` 為 0，或有延誤、警報連結時，那次回應的 `message` 和 `url` 就是該站該線的警報，note 會提示再查這個函式。這裡不另做一個下一班指令，也不做背景輪詢。

完成時能回答：運輸署現時公布的特別交通消息，不論是路面、巴士、渡輪還是港鐵。

### 特別交通及運輸安排（完成）

對應問題：這個週末、假期或工程期間，有什麼預先公布的交通安排？

核心函式 `special_traffic_arrangements` 讀資料集 `hk-td-tis_22-traffic-notices` 裡的特別交通及運輸措施，端點 `https://www.td.gov.hk/datagovhk_tis/traffic-notices/Special_Traffic_and_Transport_Arrangement.xml`。同一資料集的封路、車速、禁區等其他通告不讀。

交還通告編號、中英簡標題、生效日期和內文。生效日期沿用公布的日.月.年。內文原是 HTML，交還時去掉標籤。沒有資料時間欄，`data_at` 留空，更新頻率寫每日。全港安排都交還，不按港鐵篩選，也不快取。

完成時能回答：運輸署已公布的特別交通及運輸安排。

## 完成第一階段的標準

## 第二階段實作任務 — `bus.sh`

設計同第一階段一樣：核心層一份數據資源一個函式，回答層一條市民問題一個函式，最後一個 `bus.sh`。第一階段已有的 `_result`、`_http`、`_values`、`als`、`notices` 沿用。

### 已定的設計決定（2026-10-30）

1. **路線搜尋交還多個方案，不是一個「最佳路線」。** 市民想比較，就列幾個，每個帶成本，由市民自己揀。不對外宣稱「最快」或「最好」。
2. **成本是 `(轉車次數, 停站數)`，不是時間。** 車費有數據就逐個方案列出（未核實），冇就留空並說明。任何「較快」的講法都不會出現，除非日後有行車時間數據。
3. **A 至 B 不是坐畢全程。** 同一路線、同一方向，`seq(A) < seq(B)` 就是一段可坐的區間；圖上以相鄰站做邊，路徑自然只取中間那一段。
4. **跨營辦商站點身份本階段不做。** 九巴、城巴、新大嶼山的站號不通用，所以跨營辦商的轉車未能在圖上接上。這一點要在 note 明寫，不可以假裝找到一條跨公司路線。
5. **日後把所有模式的節點圖連成一個統一旅程圖**（重鐵、巴士、輕鐵、渡輪）。本階段先把巴士的圖同尋路做成可重用的形狀，唔預先做跨模式。
